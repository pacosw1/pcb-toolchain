# Where ESP32-CORE routing time goes (#1410)

The two complete core invocations dominate the recorded single-run wall time:
initial routing and a second route after the reference-plane check raises
`/SPI_MISO`'s cost. Together they take about **516.7 / 604.2 s (85.5%)** in the
calibration and **558.2 / 658.8 s (84.7%)** in single-a. This identifies the
dominant stage, not a proven maze-search hotspot or a parallel speedup.

Only completed #1389/#1399 records were read. No board run, CAD edit, benchmark
policy change, solver change or host configuration change was made. The ongoing
five-trial comparison remains owned by #1399; this report does not decide it.

## Recorded wall and CPU scopes

All use the frozen ESP32-CORE rev B PCB `b6b97508...` at iot-lab `a545d5e1`, seed
0 and 80 maximum passes. #1399 uses tools `228b964`, binary `3f307aa4...`,
Node 22.23.2 and the pinned `8c1c6d83...` native image. The two #1399 single
operations produce the identical `e9464aaa...` board: 956 tracks, 201 vias,
2225.0 mm. Calibration has no experiment wall cap; single-a has 960 s.

Cgroup CPU is the operation's end-minus-start counter, including descendants.
Child CPU is the owned leader's wait4 accounting, including children it reaped.
The native and gate intervals are disjoint; their descendants must not be added
again. The remaining harness wall is 0.430 / 0.542 s for the #1399 records;
remaining cgroup CPU is 0.559 / 0.686 s. No finer single-core CPU split exists.

The #1389 gate was at 4 GiB and suffered checker OOM. It is historical failure
evidence, not a comparable successful gate measurement. Its separately authorized
8 GiB gate-only check is described in [the original report](2026-11-05-plane-via-void.md).
#1399 uses 2 CPUs / 8 GiB. Its native counts and actual configured geometric and
electrical error counts are zero, but five preserved stale RP-001 exemptions
still fail the official gate. Harness status remains ERROR. These timing records
do not establish full board acceptance.

The feedback core is requested because the first written candidate fails the
existing unknown-driver reference crossing check on `/SPI_MISO`. The second
planes screen is clean. No driver edge or exemption was invented.

```text
lock/model/preflight
  -> initial core (15 passes) -> write/refill -> planes screen (SPI_MISO)
  -> raise existing reference cost
  -> feedback core (22 passes) -> write/refill -> planes screen (clean)
  -> final native DRC -> separate fresh configured gate
```

The feedback log separates 183.7 / 195.3 s through the final negotiation boundary
and 73.2 / 74.7 s of length recovery. About 1.1 / 1.0 s remains inside the
rounded core summary. Length recovery is a quality stage, not disposable work.
The initial core's detailed pass/recovery log was overwritten by the selected
feedback log; its 15-pass summary survives. It cannot be reconstructed from the
22-pass log. The feedback invocation's duration was measured internally but
discarded from the old run record.

## Preparation, checking and checkpoint coverage

|---|---|

| Model generation | No isolated single timer. Sprint-a shared preparation takes 20.771 wall / 34.252 CPU s, including model, lock and preflight. |
| Write/refill/native checks | Single native remainder above is inseparable. Sprint-a has three native-finish children totaling 40.541 child-wall / 68.655 CPU s; these include writing/refill and final native checks. |
| Configured checks | Calibration gate 34.477 s; ERC 8.823, DRC 10.137, planes 19.853, pairs 19.370, paths 20.746, via pads 8.546, labels 0.760, Happy 23.281 s. Checks overlap; their sum is not gate wall time. Single-a stage timings are in the JSON. |
| Reference feedback | Two screens and one reroute identified; screen wall/CPU and per-round writer time are unavailable. |
| Checkpointing | Singles did not request checkpoints. Sprint has 32 core slices. Four terminal logs report 18 progress-file writes totaling 0.201 s; this is partial progress-file telemetry, not total checkpoint cost. Resumable snapshot save/load and the yielded slices' progress-write costs have no separate timer. |

Completed sprint-a (`20261105-234905-945420`) took 853.380 wall / 1666.988
cgroup CPU s. Its 32 slices consumed 1345.532 child CPU s (80.7% of operation
CPU); three native-finish children consumed 68.655 CPU s and three configured
gates 207.295 CPU s. Preparation consumed 34.252 CPU s; the unattributed
cgroup remainder is 11.253 CPU s. Slice walls overlap; their 1375.822 s sum
must not be compared with the 853.380 s parent wall as elapsed overhead.
Terminal length recovery totals 390.5 child-wall s across four concurrent
variants. Its CPU is included in the slice CPU, not a second charge.

This completed sprint's controller reports FAIL/no verified candidate. Single
and sprint use different reference-feedback behavior, and official gate failure
still applies. These records do not isolate scheduler efficiency, checkpoint
overhead or an algorithm win. The remaining preregistered trials are outside
this snapshot and stay with #1399.

## What the #1325 research register justifies

| Register item | Evidence-backed next step |
|---|---|
| 6: incremental search-tree reuse | A ~258-271 s second full core after one net's reference-cost update justifies a narrowly scoped reuse/invalidation experiment. It does not show that preserving search state across changed negotiated costs is valid or faster. Keep the current full reroute as control. |
| 7: internal multicore routing | Core work dominates, so profile per-net expansion, conflict audit and length recovery next. These coarse timers do not identify one costly connection, independent regions or a conflict-safe parallel unit. Internal multicore implementation remains parked pending that evidence. |
| 2: resident native IPC | Native preparation/write/check remainder is real, but not the dominant measured cost; model/write/refill spans must be separated before choosing an IPC rewrite. The existing #1326 compatibility result also remains applicable. |
| 1 / 9: portfolios and adaptive allocation | Use the existing #1399 equal-budget comparison; no duplicate trial, early culling policy or claimed portfolio benefit is justified here. |
| 3 / 4 / 5 / 8 / 10 / 11 | No new evidence here for topology replacement, multi-label search, exact escape solvers, shove/gridless methods, GPU placement or LLM steering. Timings alone do not establish their correctness or benefit. |

The directly justified immediate work is completing the existing loop profile
(#1325's profiling recommendation and #1328/#1329), not skipping validation or
changing acceptance targets. Future finer profiling needs monotonic start/end
and reaped-child CPU by model, write/refill, plane screen and native DRC, keyed
by attempt/round. Resume save/load needs its own counter; whole-slice time
cannot supply it. Those missing historical values remain null in the JSON.

This PR makes only the smallest immediately available wrapper correction:
retain `route-initial.log` before feedback replaces the selected log and expose
the already measured `next_core_seconds`. It changes no search, ordering,
budgets, checkpoint format or acceptance rule. Existing wrapper tests pass;
no new real-board timing is claimed for the added field.

## Reproduction

[The JSON summary](2026-11-06-esp32-timing.json) records full source/binary hashes,
all consumed receipt/log hashes, CPU scopes and unavailable fields. Reproduce
it offline with `node tools/router/benchmarks/1410-timings.mjs SNAPSHOT_ROOT`.
The script checks terminal/trimmed jobs, CPU counter arithmetic, log identity,
pass counts and the sprint slice-CPU sum. No daemon or board tool is invoked.
Raw selected records are retained with the task's evidence archive; active
trial outputs and copied CAD workspaces are excluded.

Archive: CI host `/var/lib/cip/saved-artifacts/esp32-timing-1410/evidence.tar.gz`,
SHA256 `a831b9c0b0682a1fe1703778ed4921c0fdb276591987d5a9f6f2997993d3d41b`.
Extract its three inner archives into one snapshot root, placing #1389's
`after-fix` directory under `1389/`; keep `SOURCES.json` at the root. The
matching archive is also retained in this session's durable artifacts.
