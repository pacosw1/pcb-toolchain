## Remaining gaps

1. **Pour model vs KiCad starved_thermal (stop cause, 2 occurrences).** These are GND through-hole pins of J2 on
   B.Cu. `iotroute --check` gives POUR PASS for both results.
   - Run 1, J2.16 (131.65, 193.73): KiCad "1 spokes connected to isolated island". The KiCad fill island has bbox
     131.09..134.23 x 185.06..193.52. It closes where /UART_RX and /SPI_SCK converge (centre distance about 0.75 mm =
     2 x (0.2 + 0.075) + 0.2 min thickness, a zero-width channel near (134.0, 185.1)). The model piece goes through
     that point.
   - Run 6, J2.18 (134.19, 193.73): KiCad "2 spokes connected to isolated island". In the model, 3 spokes go into a
     piece with 1 item. The pour.rs fallback "no other spoke: ignored spokes count again" makes this a pass. KiCad
     fails it.
   - To reproduce: `scratchpad/m2/model3.json` + `out6.json` (`iotroute model3.json x --check out6.json`, env
     `IOTROUTE_POUR_PAD=J2.18`), and `model.json` + `out1.json` for J2.16. A fix must agree with both KiCad results
     and with the NET-CORE reference cases in pour.rs.
2. **Convergence at the gate RP-001 radius (1.0 mm).** The negotiation ends in a 2-net standoff: run 4 /LIMIT0_P vs
   /SPI_SCK in the U1 north field (U1.98 (137.00, 135.45), R20.2 (143.50, 126.85)), 2 nets open; run 6 /DIR2 vs
   /PFAILn, solved only by the end step. Each signal via also needs a GND via within 1.0 mm. This uses the room around
   the LQFP escape. The existing route avoided this with 19 RP-001 exemptions (D-143: allowed for slow nets).
3. In2.Cu (mixed layer: VDD_3V3 plane + slow signals) is not used. model.py treats every reference-plane layer as
   "no tracks". The existing route has no In2 tracks either, so the comparison is fair.
4. U5.25 has one via in the pad. The LAN8742A datasheet asks for "a via array". The existing board also has one.

## Quality of the final router route vs the existing route

Better:
- 25 % less copper length (4736 vs 6308 mm). No meanders: /AIN0 206.6 -> 51.5 mm, /VSYS_SENSE 212.2 -> 75.2,
  /GPIO_P6 141.0 -> 51.8, /SPI_SCK 161.6 -> 77.7.
- RP-001 is met on every net with no exemptions (existing: 19 exempted nets). Fewer planes warnings (3 vs 13).
  drc_warnings 31 vs 73.

Worse:
- **Too many vias:** 683 vs 526 (+30 %). Other signal vias 303 vs 211, GND 330 vs 266. Each layer change has its own
  return via beside it. Under U1 and in the board centre there is a dense field of via pairs.
- **Plane cuts:** this via field perforates In1 GND and In2 VDD_3V3 under U1 and in the centre. On B.Cu the GND pour is
  cut into narrow slivers between the parallel U1 -> J2 bundles. The existing B.Cu pour has larger solid areas.
- **Neckdowns:** power nets neck from the 0.5 mm class width to 0.3 mm on 133 segments and to 0.35 mm on 54 segments.
  The paths gate passes (paths_low 0), but the current margin is less than on the existing route (mostly 0.4 mm).
- **Detours on short nets:** /CC1 3.7 -> 12.7 mm, /VCAP 15.2 -> 23.0, /PHY_RSTn 17.6 -> 25.7, /ETH_TXD0 28.5 -> 33.5
  (RMII limit 50 mm: pass).
- Segments at any angle (not 0/45/90). There is no DRC fault, but the route is hard to review and to edit by hand.

Judgement: the router follows the rules better than the existing route (no exemptions needed, much shorter). But the
board is not yet one we would order. The via count and the plane perforation it causes are the main fault. A
return-via strategy that shares returns without congestion is the next design item, after the pour-model fix.
